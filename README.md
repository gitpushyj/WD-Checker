# 서울대 교수회관 웨딩홀 취소표 감시기

`watchlist.json` 에 적어둔 날짜와 시간대가 비면 Slack 과 메일로 알려줍니다.
10분마다 검사하고, **새로 생긴 빈자리만** 알립니다.

```
🔔 취소표 발생 — 1건
• 2027년 9월 12일 (일) 2부 13:00
  https://www.snufacultyclub.com/sub04/sub05_2?date=2027-09-12&part=2
```

## 준비 (10분)

### 1. 메일 설정

```bash
cp .env.example .env && chmod 600 .env
```

`.env` 에 본인 Gmail 주소와 **앱 비밀번호**를 넣습니다.
(`.env.example` 은 견본이라 git 에 올라갑니다. 실제 값은 반드시 `.env` 쪽에 넣으세요.)
보내는 사람도 받는 사람도 본인 계정입니다. 자기가 자기에게 보내는 구조입니다.

**앱 비밀번호는 계정 비밀번호가 아닙니다.** 2단계 인증을 켠 뒤
[myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords) 에서
16자리를 발급받으세요.

| | 계정 비밀번호 | 앱 비밀번호 |
|---|---|---|
| 메일 보내기 | ✅ | ✅ |
| 계정 로그인 · 비밀번호 변경 | ✅ | ❌ |
| Drive · Photos 접근 | ✅ | ❌ |
| 개별 폐기 | 불가 | 언제든 가능 |

유출되더라도 그 계정으로 메일을 보내는 것 외에는 할 수 있는 일이 없고,
구글 계정에서 클릭 한 번으로 무효화할 수 있습니다.

회사 계정은 관리자가 앱 비밀번호를 막아둔 경우가 많아 **개인 Gmail** 을 권합니다.
네이버 메일을 쓰려면 `.env` 에 `SMTP_HOST=smtp.naver.com` 을 추가하세요.

**비밀번호를 파일에 두기 싫다면** `SMTP_PASSWORD` 를 비워둔 채 키체인에 맡기세요.

```bash
security add-generic-password -s snu-wedding-watch -a 본인주소@gmail.com -w
```

`-w` 뒤에 아무것도 쓰지 않으면 화면에 보이지 않게 입력받습니다.
처음 한 번은 키체인 접근 허용 창이 뜰 수 있으니 **"항상 허용"** 을 눌러주세요.
그래야 자동 실행될 때도 읽을 수 있습니다.

**여러 명에게 보내려면** `MAIL_TO` 에 쉼표로 나열하면 됩니다. 세미콜론도 받습니다.

```bash
MAIL_TO=나@gmail.com, 배우자@gmail.com, 어머니@naver.com
```

비워두면 보내는 계정 자신에게만 갑니다. 주소 같지 않은 값이 섞이면 조용히 넘기지 않고
어느 값이 문제인지 알려줍니다.

설정이 맞는지 바로 확인해 보세요. 메일이 오면 끝입니다.

```bash
python3 watch.py --test-notify
```

Slack 도 함께 쓰려면 `.env` 의 `SLACK_WEBHOOK_URL` 을 채우고, 안 쓰려면 비워두면 됩니다.

### 2. 감시할 날짜 정하기

`watchlist.json` 을 편집합니다. **이 파일만 고치면 되고, 저장하면 다음 검사부터 바로 반영됩니다.**

```jsonc
{
  "targets": [
    { "date": "2027-09-12", "parts": [2, 3] },   // 하루만 콕 집어서
    { "month": "2027-10", "parts": [2] },        // 그 달 주말 전체의 2부
    { "month": "2027-10", "parts": [2, 3], "weekdays": ["sat"] }  // 토요일만
  ]
}
```

`date` 와 `month` 는 **값의 생김새로 판단**합니다. `2027-09-12` 면 그 하루,
`2027-09` 면 그 달 전체입니다. 키 이름을 바꿔 적어도 뜻대로 동작합니다.

| 부 | 1부 | 2부 | 3부 | 4부 | 5부 |
|---|---|---|---|---|---|
| 시간 | 11:00 | 13:00 | 15:00 | 17:00 | 18:30 |

`parts` 를 빼면 1~5부 전체를 봅니다. 평일은 교수회관이 특별오픈으로 지정한 날만 예약이 열립니다.

### 3. 맥에 등록하기

```bash
./install-local.sh
```

10분마다 자동 실행됩니다. 해제는 `./install-local.sh uninstall`.

## 명령어

```bash
python3 watch.py --show 2027-09   # 그 달 현황을 표로 보기 (설정 없이도 됨)
python3 watch.py --dry-run        # 알림을 보내지 않고 결과만 확인
python3 watch.py --test-notify    # 실제로 알림을 보내 설정 확인
python3 watch.py --test           # 판정 로직 테스트
python3 test_scenarios.py         # 요구사항 다섯 가지를 시나리오로 확인
tail -f watch.log                 # 감시 기록 보기

launchctl kickstart -k gui/$(id -u)/com.snu.wedding.watch   # 즉시 한 번 실행
```

## GitHub Actions 로 24시간 돌리기 (선택)

맥이 꺼져 있거나 잠자기면 그동안은 검사하지 못합니다. 백업으로 GitHub 에서도 돌릴 수 있습니다.

```bash
git init && git add -A && git commit -m "취소표 감시기"
gh repo create snu-wedding-watch --public --source=. --push
```

**public 리포를 권합니다.** private 은 Actions 무료 한도(월 2,000분)를 10분 간격으로는
넘깁니다. `watchlist.json` 에는 날짜와 시간대만 들어가므로 공개해도 문제 없습니다.
private 을 쓰려면 워크플로의 cron 을 `*/30` 이상으로 늘리세요.

리포 Settings → Secrets and variables → Actions 에서 `.env` 와 같은 이름으로 등록합니다:
`SMTP_USER`, `SMTP_PASSWORD`, `MAIL_TO` (쓴다면 `SLACK_WEBHOOK_URL` 도).
GitHub Secrets 는 암호화되어 저장되고 로그에도 찍히지 않습니다.
키체인은 맥에만 있으므로 Actions 쪽은 Secrets 를 써야 합니다.

등록 후에는 **폰의 GitHub 앱에서 `watchlist.json` 을 편집**해 조건을 바꿀 수 있습니다.

### 제대로 등록됐는지 확인하기

Actions 탭 → **취소표 감시** → **Run workflow** 에서 `mode` 를 골라 손으로 돌려볼 수 있습니다.

| mode | 하는 일 |
|---|---|
| `test-notify` | 시험 메일을 보냅니다. **Secrets 가 맞게 들어갔는지 확인할 때** 쓰세요 |
| `show` | 감시 대상 현황만 로그에 출력합니다. 메일도 안 가고 상태도 안 건드립니다 |
| `check` | 평소와 똑같이 검사합니다 (빈자리가 없으면 메일도 없습니다) |

`test-notify` 와 `show` 는 상태 파일을 커밋하지 않으므로 실제 감시에 영향을 주지 않습니다.

**스케줄은 등록 직후 바로 돌지 않습니다.** GitHub 무료 러너의 schedule 은 첫 실행까지
수십 분 걸리기도 하고, 이후에도 10분으로 적어둔 것이 실제로는 15~40분 간격이 됩니다.
급할 때는 Run workflow 로 직접 돌리세요.

⚠️ **public 리포는 60일간 활동이 없으면 스케줄이 자동으로 꺼집니다.** 봇이 만드는
상태 커밋은 활동으로 쳐주지 않을 수 있으니, 두 달에 한 번쯤은 `watchlist.json` 을
손보거나 Actions 탭에서 워크플로를 한 번 돌려주세요.

## 알아둘 것

- **맥과 GitHub 을 함께 돌리면 알림이 두 번 옵니다.** 상태 파일을 따로 쓰기 때문입니다
  (`state.local.json` / `state.github.json`). 알림 끝의 `— 로컬` / `— GitHub` 로 구분됩니다.
  놓치는 것보다 낫다고 보고 이렇게 두었습니다. 하나만 쓰려면 다른 쪽을 끄세요.
- **GitHub 무료 cron 은 지연됩니다.** 10분으로 적어도 실제로는 15~40분 간격이 되곤 합니다.
  정확한 10분은 맥 쪽이 담당합니다.
- **아직 열리지 않은 달**은 예약이 0건이라 API 상 전부 비어 보이지만 실제로는 예약할 수 없습니다.
  그런 달은 감시에서 제외하고, **열리는 순간 별도로 알립니다.** 미리 `watchlist.json` 에
  적어두세요. (2026년 9월 기준 2027년 9월까지 열려 있고, 10월은 2026년 10월에 열립니다.)
- **빈자리가 사라지면 기록도 지웁니다.** 같은 자리가 다시 나면 또 알립니다.
- **알림 발송에 실패하면 기록하지 않습니다.** 다음 검사에서 다시 시도합니다.

## 문제가 생겨도 감시는 멈추지 않습니다

| 상황 | 어떻게 되나 |
|---|---|
| `watchlist.json` 에 오타 | 한 번 알려주고, **직전까지 정상이던 설정으로 계속 감시**합니다 |
| 사이트가 응답하지 않음 | 한 번 알려주고, 기록을 그대로 둔 채 다음 검사에서 재시도합니다 |
| 일부 달만 조회 실패 | 그 달만 건너뛰고 나머지는 정상 감시합니다 |
| 상태 파일 손상 | `.corrupt` 로 옮겨두고 새로 시작합니다 |
| 그 밖의 예상 못한 오류 | 로그에 남기고 이번 검사만 건너뜁니다 |

어느 경우든 **다음 스케줄은 예정대로 실행됩니다.** 같은 문제로 10분마다 알림이
쏟아지지 않도록, 내용이 달라질 때만 한 번 알립니다.

조회에 실패한 달의 기록을 지우지 않는 것이 중요합니다. 실패를 "빈자리가 사라졌다"로
읽으면 사이트가 복구되는 순간 남아 있던 자리를 전부 새 취소표로 착각해 알림이 쏟아집니다.

## 동작 방식

페이지가 쓰는 것과 같은 JSON API 를 그대로 호출합니다. 브라우저 자동화가 필요 없어
빠르고 잘 깨지지 않습니다.

```
GET /ajax/wedding/availability?year=2027&month=9
  data    예약 완료된 부    {"2027-09-12": [1, 4]}
  closed  예약 불가한 부    {"2027-09-12": [5]}
  open    평일 특별오픈일
GET /ajax/wedding/max_open_month   현재 예약이 열린 마지막 달
```

빈자리 = 주말 1~5부 중 `data` 에도 `closed` 에도 없는 부. 페이지의 렌더링 규칙과 같습니다.

파이썬 표준 라이브러리만 사용하므로 `pip install` 이 필요 없습니다.
